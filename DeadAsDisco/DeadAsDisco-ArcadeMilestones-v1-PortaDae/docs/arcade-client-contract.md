# Arcade milestones client

Launch `python -m dad_ap.arcade_client --server ws://127.0.0.1:38281 --slot <player-name> --state-dir <root> --adapter-plan <reviewed-install-plan.json>`. Optional `--allow-remote` permits the specified outbound endpoint without changing TLS defaults, listeners or firewall rules. `--ask-password` reads a password into memory after argument and plan validation. This client does not install mods, launch the game, apply abilities or write game saves.

The v3 contract is in `dad_ap/arcade_contract.py`: game **Dead as Disco (Arcade Milestones)**, profile `arcade_milestones_v1`. Checkpoints are waves **1, 2, 3, 5, 10, 15, 20, 25, 30, 40, 50, 75, 100, 150 and 200**. Location IDs are `814000100 + wave`. Song identity and duration are not check inputs. Set Credit (`814001102`) has no gameplay effect; all moves remain available.

The generated world chooses `goal_wave` from those checkpoints, default **20**. The client reports goal only after that particular locally recorded runtime clear is acknowledged by the current server. Other checkpoints and credit receipts do not gate completion. StatusUpdate 30 is idempotently re-sent after authentication on reconnect when that condition holds. A historical local sent receipt does not suppress recovery.

State is separate under `<root>/arcade_milestones_v1/<SHA256(seed/team/slot)>`. The old one-check proof keeps its original namespace and behavior. A lifetime writer lock protects one identity; SQLite commits events/checks before submission. Duplicate locations and received-item indices do not add progress or credits twice. The goal setting is pinned for an existing seed identity.

The reviewed plan binds identity, bridge path, install/build/hook pins and staged Lua source hash. Authentication and authoritative inventory synchronization precede a ten-second check-session lease. The client renews it every two seconds until exit; there is no client session timeout. Same-second integer UTC publications increase revision without extending the consumer deadline. Reconnect uses a new nonce and requires a fresh runtime run anchor. Ctrl+C revokes authority and closes the client.

The compact milestone event contains the fresh-run anchor, current clear/confirming-advance pair, and `contiguous_clears == wave`. The runtime detector must observe every intermediate clear and advance from round 1. Python validates the pinned event and terminal pair; it does not reconstruct omitted intermediate callbacks from the compact event alone. Exact schemas are `SESSION_FIELDS` and `EVENT_FIELDS`. File ingress retains hashed archives and atomic receipts, which establish ingestion rather than independent gameplay provenance.

Four essential offline milestone tests pass: allowed IDs/goals and old-profile refusal; all 15 bounded events and duplicate persistence; goal independent of credits; configured goal and authenticated reconnect re-send. Evidence: `evidence/arcade-milestones-client-tests.log`. Earlier v2 three-clear regression/server smoke is historical and does not prove higher milestones. No live test was performed for this extension; higher waves remain unverified in-game.
